# Geoffrey Onboarding

## Goal

Help a nontechnical user reach a useful first result quickly. Do not make the user learn skills, agents, connectors, or configuration files. Translate their world into Geoffrey context, app connections, approval rules, and first workflows.

## First-Run Flow

1. Learn what the user does and what outcome they want from Geoffrey.
2. Identify where their work lives: email, calendar, files, chat, CRM, projects, code, browser apps.
3. Define safe authority boundaries.
4. Create initial context: user, business, people, projects, responsibilities, preferences.
5. Recommend only the app connections needed for the first useful workflows.
6. Identify one recurring review, briefing, or follow-up that would prevent dropped work.
7. Run one useful first task.
8. Verify the result and update context.

## Interview Style

Ask in small batches. Prefer natural questions:

- What do you do, and what do you wish Geoffrey would take off your plate first?
- Which apps contain the work Geoffrey needs to see?
- What should Geoffrey always ask before doing?
- What falls through the cracks today?
- Who are the important people Geoffrey should recognize?
- What weekly or daily check-in would make Geoffrey feel useful without being noisy?

Do not present a long technical checklist unless the user asks.

## First Useful Tasks

Offer practical starting points:

- Prepare today's briefing.
- Review active projects and identify blockers.
- Organize inbox categories and draft replies.
- Turn meeting notes into follow-ups.
- Research a decision and recommend next steps.
- Build or improve a small workflow.
- Create a short recurring review or briefing draft, then ask before enabling it.

Choose one and finish it with evidence.

## Context Seeds

Create only useful durable context:

- Voice and style preferences for drafts.
- A personal or business index of important people, projects, tools, and current priorities.
- Approval boundaries for messages, publishing, spending, deleting, deployments, and recurring automation.
- One workflow memory for a task the user repeats often.

Keep sensitive information out of memory and ask before enabling any recurring automation.

## Connection Guidance

When an app connection is needed:

1. Explain why the connection helps.
2. Ask the user to sign in or authorize through the official app flow.
3. Do not request credentials in chat.
4. Confirm access by reading a harmless signal or asking the user what they see.
5. Continue the task.

## Onboarding Output

At the end, produce:

- What Geoffrey learned.
- Which apps are connected or still missing.
- Approval boundaries.
- Active first workflows.
- Suggested next setup step.

Keep the report short and useful.
